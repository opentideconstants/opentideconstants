Data format

The fields of a release, its JSON Schema and the converters. The files and where to download them are on Downloads.

Fields

The JSON document has six top-level fields: format_version, release, conventions, licences, constituents and stations.

station
A stable station_id in the OTC namespace (never changed, never reused), name, country, position, IANA time zone, type (reference or subordinate), aliases in other systems (NOAA, GESLA, TICON, XTide, Kartverket, Slackwater), and the recommended_set_id. An alias id belongs to one station only in a release. A removed station stays as a tombstone with its reason.
constant set
One per source record: source, source type (official, gauge or model), quantity (water_level or current), record id and version, record span (start, end and hours of good data, good_hours), datum, convention_id, licence_id, QC status and flags, the constituents, and provenance. Every record stays listed. A station can have several sets; one is recommended by a published rule. A short record never outranks a set at the same station that has constants and more hours of good data, and a set with no constants is never recommended.
QC status and flags
qc_status is ok (constants, no flags), flagged (constants, and qc_flags says what to know) or no_constants (the set is listed, but no constants were fitted; no_constants_reason is too_short or fit_unusable). No value means removed. Each flag has a reason: time_base, broken_record, short_record, microtidal, non_tidal_signal or sibling_disagreement.
time-base annotation
Required on every set fitted from a gauge record (time_base): the code (verified, corrected, unverified or disputed), a reason for people, the declared and published time base, the correction from and to (only when corrected), any months left out, the build that decided it (decided_in), and the evidence: per comparison, the comparator kind and id, its distance (km) and the measured lag (minutes). A time base is a class such as utc_instant, utc_mean_start60, utc_plus_1, local_dst:Europe/Oslo or step:2010-03-01. An unverified or disputed time base also has a time_base flag. See Time-base checks.
broken record
record_issues, one per problem: datum_step, flatline, spikes, gaps, clock_step, quantised, out_of_range, unstable_constituents, neighbour_disagreement or no_tide, with where it is and why. fit_segment names the part the constants are fitted to. Comes with a broken_record flag. See Broken-record checks.
short record
A short_record flag, the record length (record_span.good_hours), the constituents left out in dropped_constituents (a Rayleigh drop names the constituent it cannot be separated from, not_separable_from), and expected_accuracy: the length long records were cut to, how many, and the expected amplitude and phase error or the expected time and height error. A record with less than about 15 days of good data is no_constants with too_short. See Short records.
constituent
OTC canonical name and the source's own name, Doodson number, speed (°/h), amplitude (m), Greenwich phase (°), uncertainties, and why it was kept. Dropped constituents are listed with the reason. Names are at most 15 characters.
constituent table
One row per constituent name and constituent-table version in the release: Doodson number, speed (°/h) and nodal formula id.
current bin
Only in a set with quantity current, which has no water-level constituents. One per depth bin: bin number, depth (m) and how it is measured (below_surface, below_chart_datum or unknown, from NOAA's S, B and U), major-axis azimuth (° true), mean flood and ebb directions, the mean current along the major and minor axes (m/s, signed), and per constituent the speed (°/h), major- and minor-axis amplitude (m/s) and Greenwich phase (°). The station's default_current_bin names the bin to show first.
subordinate offsets
Reference station, time offsets at high and low water (minutes), height offsets, and whether they are ratios or additive, as NOAA gives them. A subordinate current station has current_offsets instead, one per bin: reference station and bin, mean flood and ebb directions, time adjustments for maximum flood, slack before ebb, maximum ebb and slack before flood (minutes), and flood and ebb amplitude ratios.
convention
Phase reference, V0 model, nodal handling, constituent-table version, and the result of the per-source check that confirmed it. See Conventions.
validation
Per station and window: time mean absolute error, 95th percentile, bias, height error, range error, missed and extra events, the reference source and its distance, and the same numbers for the previous release. See Validation.
release
The datestamp, build time, upstream source versions, build commit and changelog URL, and concept_doi: the one DOI for all versions. Cite a release by the concept DOI and its datestamp. release.doi is always null: a Zenodo version DOI is made after the files are fixed, so it is only in OTC_index.json and the latest pointers (zenodo_version_doi).
licence
SPDX id (or a LicenseRef- id), provider, required citation, and the assembled attribution text. See Licence and attribution.

JSON Schema

  • otc-0.6.schema.json: the JSON Schema (draft 2020-12) for format_version 0.6. Each line of the .jsonl file validates against #/$defs/station, and the .meta.json file against #/$defs/meta.
  • otc-0.5.schema.json, otc-0.4.schema.json, otc-0.3.schema.json, otc-0.2.schema.json and otc-0.1.schema.json: the earlier versions, for format_version 0.5, 0.4, 0.3, 0.2 and 0.1. Kept for reference. 0.3 adds alias systems for the gauge and official sources (linz, shom, pegelonline, rws, mi, dmi, smhi, fmi, uhslc). 0.4 adds tidal-current constants (current_bins), current offsets and default_current_bin. 0.5 adds the mean current of a bin (mean_major_ms, mean_minor_ms) and the depth type below_chart_datum for NOAA's B, which 0.4 wrongly called above_bottom.
  • What 0.6 changes: every record stays listed, with annotations. qc_status is ok, flagged or no_constants, and 0.5's excluded is no longer valid. 0.6 adds the time-base annotation, record issues and fit segment, the short-record fields (good_hours, not_separable_from, expected_accuracy) and no_constants_reason. Deprecated for one version, and still valid: qc_status accepted (read as ok, or flagged when it has flags) and fallback (now provenance.decision.outcome), the free-text provenance.time_base (now the set's time_base: verdict becomes published, correction becomes correction from and to, comparators become evidence), and qc_flags[].verdict (now reason). release.doi is always null.
  • example.json: a small example document with illustrative values (not data). It has one tide station with two constant sets, one tombstone, one current station (NOAA ACT1616, with five of its constituents and its mean current converted from NOAA's published values), one subordinate current station, and one station with five GESLA records: a corrected time base, a broken record fitted on its usable segment, a short record with a disputed time base, a record too short for constants, and a broken record with no usable segment.

The format version is separate from the release date. A new field or enum value is a minor change, and so is an enum value that writers may no longer use, because a reader never meets a value it did not know. A removed or renamed field, or a changed unit or convention, is a major change. A deprecated field or value stays valid for one minor version.

Converters

Converters, in both directions, with a lossless round trip as a release gate: TICON CSV, XTide TCD (through libtcd), and NOAA harmonic-constant JSON. The reference predictor publishes conformance vectors (expected high and low water times and heights at named stations and dates) so that other predictors can check their results.
