Drop-in replacement for what you use now

Keep your code and your tools. Swap the data underneath them, and you get OTC's places, sets and labels with no other change.

  1. You use@slackwater/database

    Switch to@opentideconstants/tide-database

    One line in package.json, as an npm alias. Your imports and calls keep working, on Node, in the browser and on Workers, and every station id with an OTC match resolves as before. Use overrides where the database comes in through another package.

  2. You useslackwater-<date>.tcdb and SlackwaterDatabase in Swift

    Switch toOTC_<date>.tcdb

    The same database format, so the reader in your iOS or macOS app opens it. An OTC Swift package is published too.

  3. You useXTide and OpenCPN .tcd files

    Switch toOTC_<date>.tcd

    Point XTide or OpenCPN at the file. Every current bin is its own station, and the file carries OTC's own constituent tables, which XTide reads.

  4. You usethe Slackwater station JSON files

    Switch toOTC_<date>.slackwater.zip

    One file per station, in the same schema and at the same id-based paths, with a map from each id to its OTC station.

A drop-in runs on the engine you already have. For OTC's own predictions, ten times closer to the official tables, use an OTC SDK.
