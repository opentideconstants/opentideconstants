Open tide data, combined into one dataset.

OpenTideConstants (OTC) combines official agency constants, constants that we fit from gauge records, and tide-model constants into one consistent dataset: one format, declared conventions, provenance for every record, and the accuracy of every station against official predictions. It is rebuilt automatically from the latest upstream data and released under CC BY 4.0, with a DOI for each release.

This site describes the method and the format. The only accuracy numbers on this site come from a proof of concept at 11 stations, and they are labelled as such.

Three kinds of source, one release

Each source has its own licence, format and conventions. OTC reads each one with its own adapter, checks it, and writes everything into one format. At one location, official constants rank before a gauge fit, and a gauge fit before model constants.

One OTC release

OTC_{YYYYMMDD}

  • One format. JSON with a published JSON Schema, plus JSON Lines and CSV.
  • Declared conventions for every constant set.
  • Provenance for every record.
  • Accuracy for every station against official predictions.
  • Every set kept. A station lists every constant set, with one recommended by a published rule.
  • SHA-256 checksums for every file, and a DOI for each release.

Licence, attribution, access and coverage for each source are on Sources.

Why one consistent dataset matters Proof of concept

The German WSV gauge records in GESLA-4.0 are in German civil time but are labelled UTC. TICON-4 fitted them as they were, so its phases for those gauges are late. A dataset that combines sources must check every time base and convention before it uses them.

At Helgoland, the proof of concept scored TICON-4 at 88–90 min mean time error, and our fit of the same station, with the time base corrected, at 6.7 min. These are proof-of-concept numbers, not release results.

What is different

  • One dataset from many open sources

    Official constants, constants fitted from gauge records and model constants, in one format. Every station has a stable id, its aliases in other systems (NOAA, GESLA, TICON, XTide, Kartverket, Slackwater), and every constant set from every source, with one recommended by a published rule.

  • Accuracy for every station

    Every release publishes, per station, how well the constants reproduce official predictions: time and height errors, missed and extra events, and the same numbers for the previous release.

  • Declared conventions

    Every set of constants states its phase reference, time zone, astronomical-argument model, nodal corrections and constituent definitions. A converter never guesses.

  • Time bases checked

    Every input record is checked for a wrong or undeclared clock before it is used. A record whose time base cannot be explained is not used.

  • Automatic and current

    Weekly watchers detect upstream changes. A build that passes all gates is published with no person in the loop. A build that fails keeps the last good release live.

  • Open format

    JSON first, with a published JSON Schema, plus JSON Lines and CSV. Every file is named OTC_{YYYYMMDD} and comes with SHA-256 checksums.

  • Open process

    The site source and the issue tracker are public on GitHub. Anyone can report a problem with a station there.
