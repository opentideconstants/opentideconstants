Method

How a release is built, from the source records to the published files.

Fitting

For a visual walk-through of constituents, phase and record length, see Tide Mechanics.

  • Basis: least squares on the reference predictor's own equation, h(t) = Z0 + c·(t − t̄) + Σ fk·(ak cos Xk + bk sin Xk), where Xk = speedk·t + (V0+u)k. Speeds, V0+u and f come from the same tables the predictor uses. The fitted constants therefore plug into the predictor exactly, and the convention mismatches on the Why page cannot arise.
  • Span: the last 19 years of good data (one nodal cycle is 18.61 years). A shorter record is fitted whole, however short it is. See Short records. A linear trend is fitted alongside, so sea-level rise does not leak into the annual constituent.
  • Quality control before fitting: null values, values flagged as not usable, and duplicate time stamps are dropped. Sub-hourly records are reduced to one value per hour. Spikes are removed against a rolling median of the residual, and the fit is repeated.
  • Uncertainty: for each constituent, the larger of the residual noise in its frequency band and half the difference between fits to the two halves of the span.
  • Determinism: fixed random seeds, sorted inputs, fixed output precision. Two builds from the same inputs must give byte-identical files.

Time-base checks

Every record is checked for a wrong or undeclared clock. When no comparator gives a verdict, a record keeps the time base that GESLA declares for it. A record whose time base OTC disputes or cannot resolve is not published, and neither is a third-party analysis of it (see Third-party analyses below). The metadata cannot be trusted for this: in GESLA-4.1, 6,681 of 6,682 records declare a time zone offset of 0, including records that are not UTC. Phase and time base in Tide Mechanics shows how a clock offset moves each phase.

  1. Comparators, in order of preference: official predictions near the gauge (official_predictions); official harmonic constants, such as NOAA's for NOAA records (official_constants); other records at the same gauge from a different contributor, after their own correction (sibling_record); the verdict of the provider's other records (provider). When none of these gives a verdict, three weak checks: a global tide model, EOT20 (model); the constants already served for the location (served_constants); and the record's own daylight-saving test (dst_selftest). Each comparison records its lag in minutes: the record's time stamp of an event minus the comparator's time of it.
  2. Measurements: the monthly time lag at 1-min resolution, the lag per constituent, amplitude ratios, a direct test of instantaneous against averaged sampling, and the missing hour on daylight-saving change days.
  3. Verdict classes, each with a fixed correction: UTC instantaneous; UTC hourly mean stamped at the start of the hour (shift +30 min and correct the amplitudes); UTC plus or minus a whole number of hours; local time with daylight saving; a step at a date. Isolated bad months are not a class: they are left out of the fit under any class, and the annotation lists them (months_dropped).
  4. Pass rule: a correction is made only on positive evidence. After the correction, the residual M2 lag must be within ±3 min in every month used.
  5. Annotation: every record carries one of four time-base annotations. Verified: the evidence confirms the declared time base, and the evidence is listed. Corrected: the time base is changed, and the annotation states from what to what and the evidence. Unverified: no comparator gives a verdict, so GESLA's declared time base is kept; the annotation can list the checks it tried. Disputed: the evidence disagrees with the declared time base but no class explains it, so the record is not published.
  6. Third-party analyses: a set of constants that a third party fitted from a record (source type analysis, TICON-4) carries OTC's annotation of the same record. Verified or unverified: the constants are carried as published. Corrected: OTC applies the same correction to the publisher's phases, and the set says so in provenance.modified. Disputed: the set is not carried, and neither is OTC's own fit of the record.
  7. Comparator codes: The build's time-base audit uses short internal codes for its comparators, and they map to comparator_kind as: b (official predictions) → official_predictions, c (official harmonic constants) → official_constants, a (another record at the gauge) → sibling_record, inherit (the provider's other records) → provider, and w (the weak checks) → model (EOT20), served_constants or dst_selftest, by the check that gave the verdict.
  8. Positive controls on every build: pinned GESLA-4.0 WSV files must come out as local time with daylight saving; a record shifted by +60 min must be detected; an hourly-averaged copy must be detected. If a control fails, the build stops.

Broken-record checks

The checks remove spikes, and refuse a fit whose main constituents differ between the two halves of the record, whose own uncertainty is too large, or that is implausible against nearby gauges or EOT20. A refused record is not published.

The fields are on Data format.

Record selection

When several records exist at one gauge, the build picks one by fixed rules, in this order: a record whose time base is not disputed; a record that is not short; instantaneous before averaged; sub-hourly before hourly; a current record (one that ends within 2 years of the newest) before older ones; the gauge operator's own record before a re-distribution of it; a licence that allows commercial use; the most good data in 2002–2020; the most recent; research-quality before fast-delivery data; then the record id. A short record never comes before a record with constants and more hours of good data, and a record with no constants is never chosen. When two eligible records disagree beyond their uncertainty, the record with the lower error against an official reference is chosen. The build records every choice and the rule that decided it. A third party's published constants for a gauge (source type analysis) are not a record that OTC fits, so they take no part in this selection: they rank below any OTC gauge fit at the station (see How sources rank).

Constituent selection

  1. Candidates: every constituent the predictor's tables define: NOAA's 37 plus EPS2, MKS2, SIG1, N4, S3, 2MK5, 2MO5 and 2MS6, in a fixed priority order.
  2. Record length (Rayleigh rule): a candidate is kept only when the record is long enough to separate it from every higher-priority constituent already kept. See Record length in Tide Mechanics.
  3. Signal to noise: after a first fit, a constituent is kept only when its amplitude is at least twice the residual noise in its frequency band. Then the fit is repeated.
  4. Long-period constituents (SA, SSA, MM, MF, MSF) are left out of the published set at river and lake gauges, and where SA is 0.25 m or more, because official predictions do not contain river and seasonal discharge signals.
  5. Non-tidal daily cycles (S1, S3, S4) are left out at river and lake gauges, and where they are larger than both M2 and K1.

At the validation stations this keeps 41–45 constituents for 19-year records and 23–28 for records of 1.5–2.5 years. Every dropped constituent in a release records why it was dropped.

Short records

A short record is published when the accuracy calibration covers it. Otherwise it is not published.

  • The fit solves only the constituents that the record's own good data can resolve, by the record-length rule in Constituent selection.
  • Each short record is flagged and notes its length (hours of good data, and the span), each constituent left out with its reason (for example P1, which a 40-day record cannot separate from K1), and an expected-accuracy indicator: the expected amplitude and phase error, or the expected error of high- and low-water times and heights. The indicator is measured on long records cut down to the same length.
  • A record with less than about 15 days of good data (release.fit_min_good_hours) gets no constants and is not published.
  • In the combined dataset, a short record never outranks a set at the same station that has constants and more hours of good data, whatever their source types, and a set with no constants is never recommended. See Record selection.

Per-source convention check

Every source is compared on every build with an independent comparator at the same gauges: our own GESLA fit, predicted with the reference predictor. The pass rule is that the median M2, S2, K1 and O1 differences are within 1 cm and 2° over at least 3 overlapping gauges. The first release has no earlier release to carry constants from, so no set in it is flagged carried_over. A failed source check never drops a GESLA record. A source with no overlapping gauge cannot be added.

Automation

  • Builds run locally, not on GitHub Actions. Every build is a full rebuild.
  • A monthly GitHub Actions workflow (harmonics-data-monitor.yml, in the webcaltides repository) checks for new XTide and TICON releases and for changes to NOAA's station types.
  • A daily GitHub Actions workflow (pegelonline-harvest.yml) harvests PEGELONLINE records into OTC's own archive.
  • There is no weekly watcher for each source.

The release gate

Every judgement in a build is made by fixed rules, and the build refuses what the rules cannot accept. Reviewed exceptions are kept in public files in the pipeline repository: timebase_reviewed_withhold.json (records withheld for their time base after a review), and station_decisions.json and station_review.json (which records form one station).

A release is written only when the release document passes the schema and cross-reference checks. The release files are complete only when the checksum file names every file and matches it, and an upload must pass that check first. If a check fails, nothing is published; after the first release, the last good release stays live. Licence and publication policy stay with the project owner and never block a build.
